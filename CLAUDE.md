# Notes for Claude (maintainers' sessions)

## Branches

- **`main` is stable.** Users' clones follow it, and the panel's Update button pulls it. Within about 10 minutes of `VERSION` changing on `main`, every panel shows the update bar. So `main` changes only through a release (below), never through a direct commit or a fix or feature PR.
- **`test` is where changes land first.** Work on `test` itself: commit there and push to `test` (`git push origin test`). Don't create feature branches or open PRs for your own changes, and don't leave work on a side branch. The flow is always `test` → `main`, through a release. GitHub's default branch stays `main`, so check you're on `test` before you commit.
- **To try `test` yourself:** in the clone `install.ps1` ran from, `git switch test`, `git pull`, close KiCad, `install.ps1 -Update`. The panel's Update button then pulls `test`. The bar only appears for a newer stable `VERSION`, not for new `test` commits. Switch back with `git switch main`.

## Handling issues

Problem reports from the panel arrive as public issues on odtu/PowerLabKiCadAssistant.

1. Fix the problem, verify it, and commit the fix to `test` and push it, with `Fixes #N` in the commit message. GitHub closes the issue when that commit reaches `main` in a release.
2. **Always reply on the issue** after a fix: what went wrong, which commit fixed it, how it was verified, and what the reporter must do to get it (usually: pull, close KiCad, rerun `install.ps1`).
3. **Post replies as `github-actions[bot]`, never under a maintainer's personal account.** Don't use a GitHub tool or `gh issue comment` that posts as the signed-in user. Write the reply to a file and run the `reply-to-issue.yml` workflow:

   ```powershell
   gh workflow run reply-to-issue.yml -R odtu/PowerLabKiCadAssistant -f issue=N -F body=@reply.md
   ```

   Add `-f close=true` to close the issue too. Use `-F body=@file`: Windows PowerShell 5.1 mangles quotes in inline arguments. After the run, check the comment author is `github-actions[bot]`.
4. Issues and replies are public. Never quote project, board, sheet or part names, net names or file contents from a user's design in a reply.

## Automatic issue fixing

`.github/workflows/auto-fix.yml` runs Claude (claude-code-action) on GitHub when:
- a member or collaborator opens an issue, or
- a maintainer adds the `auto-fix` label to anyone's issue.

Claude reproduces the bug with a test, fixes it and runs the tests. The workflow then opens a pull request into `test` (`Fixes #N`) and comments on the issue as `github-actions[bot]`. Its changes are limited to `plugin/`, `tests/`, `tools/`, `patches/kicad-mcp.patch`, `README.md` and the install scripts. Most reports are about the KiCad MCP server's tools, so the workflow checks the server out at the pin with the patch applied (`tools/mcp_patch.py checkout`); Claude fixes it there and `tools/mcp_patch.py regen` writes the change into the patch. Claude can't edit `CLAUDE.md`, so its summary gives the line for "Fixes to the KiCad MCP server"; add it when you merge.

A maintainer still reviews and merges the PR, tests it on `test`, then releases (below) and replies with the version. The workflow file itself runs from `main`, so changes to it take effect once released. Bugs that need the KiCad window can't be verified on the runner; Claude lists them under "Needs a human".

**Limits.** Runs use the maintainer's Claude subscription (the `CLAUDE_CODE_OAUTH_TOKEN` secret), so they count against the same usage limits as their own Claude use.
- **Model:** Opus 5.5 at high effort.
- **Per run:** up to 60 turns and 60 minutes.
- **Per day:** at most `DAILY_LIMIT` (3) successful or running Claude runs in 24 hours. Over the limit, the bot says so on the issue; re-add the `auto-fix` label later to retry.

## Releasing

Users only learn about fixes through releases. Every panel reads `VERSION` from `main` every 5 minutes (`updates.py`), and offers an update when it is newer than its own. The bar's text comes from the GitHub release of that version.

1. On `test`, bump `VERSION` in `plugin/powerlab_assistant/config.py` (semantic: patch for fixes, minor for features).
2. Merge `test` into `main` with a merge commit, not a squash, so the two branches stay in step:

   ```powershell
   gh pr create -R odtu/PowerLabKiCadAssistant --base main --head test --title "Release X.Y.Z" --body-file notes.md
   gh pr merge <PR> -R odtu/PowerLabKiCadAssistant --merge
   ```

   Merging is the release: within about 10 minutes every panel shows the update bar.
3. Right away, tag and publish the release on `main`:

   ```powershell
   gh release create vX.Y.Z -R odtu/PowerLabKiCadAssistant --target main --title "X.Y.Z" --notes-file notes.md
   ```

   The first bullet of the notes appears in the panel's update bar ("PowerLab Assistant X.Y.Z is available: <first bullet>"). Make it a short, user-facing summary. Until the release exists, the bar shows without it.
4. Never commit to `main` directly, not even docs: anything on `main` reaches users with their next Update.
5. Issue replies name the version that contains the fix ("Fixed in 0.1.1 — update from the panel"), so reporters know which update brings it.
6. If the release changes the pinned KiCad MCP server commit, change `$McpCommit` in `install.ps1`. `install.ps1 -Update` rebuilds it only when that pin or `patches/kicad-mcp.patch` changed.

## Fixes to the KiCad MCP server

`patches/kicad-mcp.patch` holds the lab's fixes on top of the pinned `$McpCommit`. Since 1.0 the panel doesn't use Freerouting: install.ps1 no longer installs Java or Freerouting (and removes old copies), and the panel blocks `autoroute`, `check_freerouting`, `export_dsn` and `import_ses` (`DISALLOWED_TOOLS`). The Freerouting fixes below stay in the patch for now; `freerouting_live.py`'s `LiveCopper` is what the PowerLab router's live display uses. The installer checks whether it's applied (`git apply --check -R`); if not, it resets the checkout to the pin, applies the patch and rebuilds. Today it does these things:
- **Rotation keeps 3D models:** `move_component` puts them back, because kipy 0.8's orientation setter drops them (#10).
- **`pourNets` on `autoroute`:** those nets are left out of the DSN, so they connect through pours instead of tracks; their existing tracks are kept.
- **`keepoutPourNets` on `autoroute`:** left out like `pourNets`, but each pour's outline becomes a keepout on its layer, so Freerouting routes around outer-layer power pours instead of reading them as solid planes.
- **Freerouting analytics off:** the CLI and Docker commands pass `--usage_and_diagnostic_data.disable_analytics=true`, like the live API server.
- **Via drills after the SES import:** a session via whose annular ring is below the board minimum gets a smaller drill.
- **`clean_up_routing` (new tool):** after autorouting, removes router stubs and dead-end tracks, widens tracks to their net-class width, and chamfers 90° corners. Each change that adds copper is checked with kicad-cli DRC (zones refilled, `--all-track-errors`, because by default a track already in one error hides its others) and taken back if it adds an error. Ported from the post-route scripts in odtu/PCBDesignWClaude (`hardware/tools/pcb`).
- **Deleting in live mode (#56):** `delete_trace` fell back to the tool's offline copy and reported success, so nothing changed in KiCad. It now deletes tracks and vias in KiCad's board (UUID, position, net; locked copper kept; nothing found is a failure). `list_graphics`, `delete_graphic` and `clear_board_outline` got live handlers too, for board-outline edits.
- **"No board is loaded" in live sessions (#57):** a tool that works on the saved board (e.g. `run_drc`) answered that while KiCad had the board open, until `open_board` was called. The dispatcher now loads the board it names, the session's, or KiCad's open one, and runs the tool once more.
- **Pad connection on pours:** `add_copper_pour` takes `padConnection` (`thermal`, the default, or `solid` for high-current power pours) and `priority`, in both modes.
- **Pours in live mode (#12):** the live `add_copper_pour` handler accepts the tool's `outline` (or `points`), and falls back to the board outline like the offline one. `add_zone` gets a handler in both modes.
- **Stitching vias in live mode (#14):** `add_gnd_stitching_vias` had no live-mode handler. With KiCad open, the tool process never loads the board, so it said "No board is loaded". The new handler plans on the saved board file with the largest net-class clearance, then places the vias live.
- **Footprint text in live mode (#36):** `move_footprint_text` had no live-mode handler, so it moved the text on the tool's offline copy and the next save wrote KiCad's live board over it. The new handler moves the reference, value or a user field/text in KiCad directly.
- **Live autorouting (`live` on `autoroute`, prototype):** with the board open and saved in KiCad, Freerouting runs as a local API server (`commands/freerouting_live.py`, authentication and analytics off). Every `liveInterval` seconds (default 2) its partial session is imported into a scratch copy of the board, and the new copper is pushed into KiCad over kipy in one commit, replacing the previous update; existing and locked copper isn't touched. At the end the normal SES import runs, KiCad's board is brought in line with it (locked copper kept) and saved there, so no File → Revert. One attempt only; not in Docker.
- **Undoing an autoroute run (`undo_autoroute`, new tool):** the run writes the routed board over the saved file, so File → Revert can't undo it. Each successful run keeps the saved board from before it in `autoroute-backup\` next to the board (`commands/autoroute_backup.py`); `undo_autoroute` copies it back, reloads the board and removes the copy, so it works once. With KiCad open on the board, it puts the old copper back into KiCad's board instead, refills the zones and saves there, so no File → Revert. `powerlab_route` runs keep the same backup.
- **PowerLab router (`powerlab_route` and `powerlab_route_status`, new tools; `commands/powerlab_router/`):** a router that applies the lab rules while routing; see `docs/powerlab-router-plan.md`. A run takes 10–15 minutes on TestPCB, so `powerlab_route` starts it in a KiCad Python process of its own (`commands/powerlab_route.py`) on a copy of the saved board and returns. It routes the Default-class nets from scratch like `tools/router_bench.py`, plus the other nets that have no tracks yet (power rails first, at their class width), or `nets`; it leaves out pour nets, nets with locked copper and other-class nets that already have tracks. With KiCad open on the board, the router process connects to KiCad itself (the worker passes its socket and token in `job.json`) and pushes its copper into KiCad at most every 2 s (`_Live`, one commit each, pours unfilled meanwhile); `live.json` records what it last showed, so `apply()` can tell that from a user edit, and a failed or stopped run puts KiCad's copper back as saved. A net's later connections may end on its earlier tracks (a T-junction, `tree` in `model.route`), so no second track runs beside the first; lanes a track already leaves a pad by cost more, and overlapping collinear tracks of a net are merged at the end. Pads that aren't fine pitch may be entered at 45°. After routing: `finish.py` straightens with a corner cost (and checks the pour on KiCad's fill instead of the hug costs), a second look reroutes the worst detours, then `pours.py` adds a pour round each power rail's tracks (thermal reliefs unless `solidPourNets`) and GND stitching vias (`stitchPitch`, 5 mm). `powerlab_route_status` waits up to `wait` seconds and reports progress; when the run is done, it keeps the backup and puts the result into KiCad's open board (zones refilled, saved there) or over the saved file. It refuses to start while KiCad's board differs from the saved file, and doesn't apply a result to a board changed during the run. It reads the board's `.kicad_dru` clearance rules itself (`rules.py`), because KiCad's rule engine isn't available from Python. It rips up and reroutes blocked connections and straightens the result (`finish.py`). The lab rules are search costs (`costs.py`): pours kept whole, no tracks under magnetics, escape room at fine-pitch pins, switching nets off power-pour layers, clock spacing, escape vias at the pins. Like hand routing, a bus between two parallel pin rows is drawn as a river (`bus.py`), with escape vias in a column and a bundle on the other layer where one layer is full, and other runs are redrawn as simple 45° shapes (`patterns.py`). `tools/router_bench.py` runs it on a board and compares it with DRC; `tools/route_quality.py` measures routing quality (pour pieces, pad entries, corners, vias), e.g. against the hand-routed TestPCB.
- **Router on big boards (TestPCB2, 4 layers, 266 connections):** a run there reached 74 connections in 31 min at 5.8 GB. Three causes, three fixes:
  - grids per net: rules that name nets (`A.NetName == ...`) gave every net its own `_Occupancy`, each holding full-board arrays for every net and layer. Now nets the rules can't tell apart share one (`RouterBoard.net_group`: same pattern matches, then the same clearance to everything), and a net's copper is a `Patch` (just the box round it, `grid.py`);
  - inner planes: inner layers mostly covered by zones (`plane_layers`) aren't routed, vias pass through; `routeLayers` overrides;
  - stalls: a connection's searches stop after `CONNECTION_SECONDS` (90 s; then no rip-up), the routing stops after `timeLimit` minutes (15) and the run finishes what it has, for hand routing. The status reports `per_minute`, `eta_minutes` and `stalled_seconds` (nothing routed for 3 min).
  Now: 94 connections in 5 min at about 1 GB; most of the rest fail on "no free entry lane", i.e. the placement.
- **Buses keep out of rule areas:** a bus's river tracks and escape vias (`bus.py`) are placed with the exact clearance check, which doesn't see rule areas, so they ran through "no tracks / no vias" keep-outs that the search kept out of. `_clear_on` and `_via_fits` now check the keepout grid too (first: it's cheap). `_outside_keepouts` checks a run's points at once with numpy and only the board's bounds when there are no rule areas, because bus planning calls it tens of thousands of times.
- **`check_part_spacing` (new tool, `commands/part_spacing.py`):** the lab's parts have no courtyard, so DRC can't see parts packed pad to pad. It measures pad-to-pad gaps between parts on a side (1 mm, 2 mm round fine-pitch ICs), overlapping bodies, parts in keep-out areas (rule areas, plus circles, rings or polygons from the call, per side) and pads near the edge. The review and placement skills run it.
- **Board views for review:** `get_board_2d_view` renders in layer colours on KiCad's dark background (it was black and white), keeps the board's aspect ratio, and takes an `outputPath`, so the `powerlab-visual-review` skill can keep a numbered series. `region` renders a close-up (the SVG's viewBox narrowed to it), because whole-board views hid the crowding on TestPCB2.
- **Placed symbols keep their library fields:** placement (`add_schematic_component`, the batch tools, `replace_schematic_component`) wrote only Reference/Value/Footprint/Datasheet/Description and used the symbol's *name* as the Value. A lab part named `22 µF 100V` lost its MPN, ratings and distributor numbers, and showed `22 µF 100V` instead of `22 µF` with the Voltage Rating field under it. Now every library field is copied with the library's position, visibility and show-name, and the Value comes from the library. Field offsets were also drawn upside down (library y-up). `replace_schematic_component` carries over only fields edited on the placed part, so a replacement part gets its own MPN and Value. `update_symbol_from_library` (`syncFields`, on by default) repairs parts placed before: it adds the missing fields (ratings stacked under the instance's Value, at its angle) and resets a Value that is just the symbol name.
- **KiCad path variables in symbol libraries:** `${METUPOWERLAB_SYMBOLS}` and other variables from `kicad_common.json` now resolve, so lab parts can be placed without a temporary project library entry.
- **Live edits KiCad's API can't do (#63, #65, #67):** KiCad 10.0.5's API can't load a library footprint (`ParseAndCreateItemsFromString` is an empty stub; pcbnew has no `GetGlobalFootprintLib`). So `place_component`, `add_mounting_hole`, `sync_schematic_to_board`, `edit_component` and a few more changed the tool's offline copy, and KiCad never showed it. With KiCad open on the board they now run on its saved file (`LIVE_VIA_FILE_COMMANDS`): KiCad saves, the SWIG handler edits the file, KiCad reverts to it. KiCad's undo history starts again there. `replace_component` had a tool but no Python command; it now swaps a footprint, or reloads it from its library, like `edit_component`. `add_mounting_hole` takes `plated` and `net`.
- **Flipping live (#64, #66):** `move_component` ignored `layer` live. It now flips with `FlipItems` (KiCad 10.0.6+), or by selecting the part and running KiCad's flip action, then places the part at the angle asked for (or its old one). Offline place, move and footprint exchange also set the angle after the flip, since Flip mirrors it (30° became 150°).
- **Update PCB from Schematic (#65):** `sync_schematic_to_board` takes pad nets from KiCad's own netlist (`kicad-cli sch export netlist`, the one F8 uses), not from its own schematic parser. That parser missed local labels on the middle of a wire and dropped the `/Sheet/` prefix. A net renamed this way takes its tracks, vias and zones with it, as F8 does.
- **Round outlines live (#68):** `add_board_outline` with `shape: "circle"` draws the Edge.Cuts circle in KiCad.
- **Schematic text (#60):** `delete_schematic_text` and `move_schematic_text` find a text by uuid, or by its text and position. `list_schematic_texts` shows uuids and text boxes.
- **Junctions (#62):** the wire tools' junction sync counted only wire ends and pins. A T drawn in KiCad (a wire ending on the middle of another) therefore lost its junction at every wire edit on the sheet. A wire running through the point now counts twice, as in KiCad.
- **`open_board` timeout (#61):** with 300+ symbol libraries, resolving them re-read `kicad_common.json` and probed the KiCad folders once per library: ~27 s against a 30 s limit. Now it's done once per load (~3 s), and `open_board`/`open_project` get the long timeout.
- **Pad nets (`padNets` on `edit_component`):** no tool could set the net of a pad already on the board, so plated mounting holes stayed without GND. `{"*": "GND"}` sets every plated pad, `{"1": ""}` clears one; a missing net is created. Live it runs on the saved file like the rest of `edit_component`.
- **Schematic net-class styling:** `create_netclass` takes `patterns`, `schematicColor`, `wireWidth` (mm) and `projectPath`, so the §1.6 GND/Power classes (blue/red, 0.3 mm) can be set at the schematic stage without a board.
- **Board text (#70):** text placed with `add_board_text` couldn't be changed or removed: live, `list_graphics` and `delete_graphic` read only KiCad's shapes, and no tool edited board text. Now `list_graphics` lists board text and text boxes too (text, position, size, thickness, angle, mirroring), live and offline, and its layer filter takes either name (`F.SilkS` or KiCad 10's `F.Silkscreen`); `delete_graphic` deletes them. The new `edit_board_text` changes a text's content, position, layer, size, thickness, angle or mirroring by uuid (live in one commit). Live `add_board_text` now keeps `size`, `rotation`, `thickness`, the position's unit and layers other than silkscreen/copper, and returns the new text's uuid, as the offline one does.

To change it:
1. Edit the files in `%LOCALAPPDATA%\PowerLabKiCadAssistant\KiCAD-MCP-Server`.
2. Regenerate the patch with `python tools/mcp_patch.py regen` (it takes the checkout's folder; that one is the default). It keeps the MIT license header (everything before the first `diff --git`, which `git apply` ignores) and includes new files. By hand: `git add -N <new files>; git diff <pin> > <repo>\patches\kicad-mcp.patch`, `git reset`, then put the header back.
3. Check that it applies to a clean checkout of the pin.
4. `install.ps1 -Update` rebuilds the server when the patch differs from the one its build was made from (`dist\.powerlab-patch`, the patch's SHA-256), so your own checkout is rebuilt too, not only users' fresh ones.

## Skills

- **Where they live:** each folder in `skills/` is a Claude Code skill (`SKILL.md` with `name` and `description` frontmatter). `install.ps1` (and `-Update`) copies them to `%USERPROFILE%\.claude\skills\`. Name them `powerlab-*`: the installer removes `powerlab-*` skills that no longer ship, and never touches the user's other skills.
- **Writing one:** the description decides when Claude uses it, so name the user phrasings. Keep the body to the lab's procedure and judgement; the kicad MCP tools do the work.
- **External tools:** a skill that needs one gets it from `install.ps1`. Pin the version and its SHA-256, install it under `%LOCALAPPDATA%\PowerLabKiCadAssistant`, record its path in `config.json`, and expose it to the panel's sessions in `common.clean_env()`. (Java 25 and Freerouting 2.4.1 were set up that way until 1.0.) Never change system-wide PATH or Java.
- **The `Skill` tool** is in the panel's `ALLOWED_TOOLS`.
- **`powerlab-pcb-design-rules`** is a copy of the lab's [PCB_DESIGN_RULES.md](https://github.com/odtu/Powerlab/blob/master/KiCAD/PCB_DESIGN_RULES.md). It differs in two ways:
  - it is renamed, with a `Source:` line under the title;
  - nothing lab-branded goes on other people's boards: the drawing-sheet template rule (§1.1, and its §1.9 checklist item) is removed, and §3.6 has no lab logo, website or QR code. Instead, every board gets the silkscreen text `Designed with PowerLab KiCad Assistant and Claude` (and its §3.7 checklist item).

  - it has a §4 that points to `handbook/`.

  When the source changes, copy it again with the same edits. Change rules in the lab's file too (a PR to odtu/Powerlab), so the two stay the same. §3.3 pours, §3.4 routing, §3.5 vias: other skills (autoroute, visual review) refer to these numbers, so check they still match. `PANEL_NOTE` tells Claude to load it for any design work.
- **The review handbook** (`skills/powerlab-pcb-design-rules/handbook/`) is a copy of `pcb-handbook/` in odtu/PCBDesignWClaude (233 rules from online reviews and app notes), without `PROGRESS.md` and without the links to the Turkish working notes in `90-visual-audit-guide.md` and `SOURCES.md`. Copy it again when the source changes; the tests count 233 unique rule IDs, so update that number with it.
- **`powerlab-placement`** starts every placement with a block plan and asks the user before placing any part. Claude writes `placementlock-plan.json` (blocks as shapes in board mm, their side, parts and links); when the Write or Edit succeeds, the panel (`plan.py`) shows it in the chat as one row with Open, which opens the card in a window of its own (`CardWindow`: the panel's page with `<body class="window">`, passing the card's clicks, drags and "send" to the panel, and redrawn when Claude writes the file again). The card: the board, top blocks solid and bottom ones hatched, a Top/Bottom switch and a block list. Hovering a block lights it and its row; a click sends its `refs=` to the same `locate` as review links, so KiCad selects the parts and cross-probes them into the schematic. The user can drag blocks (sectors turn round their centre and move in or out, other shapes move in x and y, snapped to 0.5 mm / 0.5°). Near the board's lines a drag snaps to them instead, with dashed guides: a block's side flush with the board's edge, its middle on the board's middle lines (so the middle of an edge, a corner or the centre, from the board's box in `data-board`), a sector's middle on 45° steps round its centre; Alt drags freely or switch a selected block's side. Boxes and polygons turn: ↻ 90°, ↻ 45° and ↺ 45° first, then any angle typed in. `"outline": "board"` draws the board's Edge.Cuts (`plan.edge_cuts` reads lines, arcs, circles, rects, polygons and curves from the saved file's text and chains them into loops, largest first; not `pcbnew.LoadBoard`, which inside KiCad can switch its open project). Footprints' own Edge.Cuts aren't read. Board texts and logos are blocks too (`kind` `text` / `logo`, drawn like silkscreen); a block without `refs` (board text has no reference) is located at its centre (`at=`). While a block is dragged, its links follow it with the edge-to-edge gap measured live (`data-pts` outlines); after the drop, `plan.relabel` writes that gap into the moved links' labels (`gate A · 7.5 mm gap`). Each move goes to `msg_plan_move`, which writes it into the file (`plan.move`, only plans in the chat's project) and redraws the card; "Send moves to Claude" sends the list of moves as the user's message, and Undo sends the opposite move. Its ranking puts gate drive and hot loops first: the driver in the middle of its switches, the MCU moves (from TestPCB2's 40 mm leg-C gate lines and the lab's cycloid driver, which is in a private repo: don't name it in the skill).
- **`powerlab-design-review`** runs at the end of placement and routing: review, fix, check again, then write `design-review\design-review.md` in the project. When a run's Write or Edit of a file with that name succeeds, the panel (`review.py`) shows the review after Claude's reply as one row with Open (the whole review in its own `CardWindow`) and PDF, and prints it to `design-review.pdf` with headless Microsoft Edge (its own temporary profile, so it never touches the user's Edge). Without Edge, it saves `design-review.html` instead. Places in the review (and in Claude's replies) are `kicad:` links (`refs=`, `net=`, `area=`, `at=`; `review.parse_location`). A click selects them in the PCB editor over the API (`KiCadSource.locate`), runs KiCad's zoom-to-selection and, for nets, highlight-net actions, and KiCad's own cross-probing then selects them in the schematic editor. KiCad 10's schematic API has no selection, so this needs the PCB editor open.

## Working on the code

- Stage only the files you changed (`git add <paths>`), never `git add -A` / `git add .`. Maintainers keep local KiCad test projects in the checkout (e.g. `tests/TestPCB/`), and KiCad lock files contain the user's computer and user name.

- Tests: `"C:\Program Files\KiCad\10.0\bin\python.exe" -m unittest discover -s tests` (KiCad's Python has wx and pcbnew).
- `install.ps1` / `uninstall.ps1` must stay plain ASCII and run on Windows PowerShell 5.1. Under `$ErrorActionPreference = "Stop"`, redirecting a native command's stderr (`*> $null`, `2>&1`) throws; run such checks through `Probe`.
- The panel promises users that nothing about their projects reaches METU Power Lab. Anything added to problem reports must go through `report.scrub`, and must never include messages, Claude's replies, selection, clipboard, or project/part/net names.
